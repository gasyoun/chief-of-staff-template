# /fleet-act — командование флотом (с подтверждением)

Порядок всегда один: сначала `/fleet-check`, затем **предложение** владельцу в виде
«ситуация → команда → что изменится», и только явное «да» в этом же диалоге открывает
исполнение. Без «да» скилл ничего не делает — это не формальность, а граница.

Каталог команд (Mac-сторона, документированные пути):

| Ситуация | Команда после «да» |
|---|---|
| Mac-лейн завис/умер | `launchctl kickstart -k gui/$(id -u)/com.gasyoun.hermes.<name>` |
| Пере-проба исполнительного лейна | `cd ~/Documents/GitHub/Uprava && python3 tools/lanes_probe.py <lane>` |
| Запуск дренажной волны | лончер: `drain_night_launch.py run --bucket handoffs` |
| Рестарт фермы по расписанию | только тот launchd-джоб, что назван во `me/fleet.md` |

Вне каталога (серверная часть `/home/hermes/bin/`, правки `lanes.tsv`, новые джобы):
CoS предлагает формулировку, исполняет владелец или отдельный согласованный проход —
сам не ходит. Реестр `lanes.tsv` правится только через запрос на слияние (pull request)
в общий репозиторий управы Uprava — так правки попадают на ревью и в историю, а не
напрямую в работающий файл.

После исполнения — запись в `me/log/YYYY-MM-DD.md`: команда, кто подтвердил, вывод,
стал ли лучше статус в `/fleet-check`. Отказ владельца тоже записывается.

Запрещено без исключений: `git push` в чужие репо из этого репо, удаления, авто-рестарты
по таймеру, действия по 152-ФЗ-ограждению.
